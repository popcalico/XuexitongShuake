## 26.11.22.1216（2026-11-22 12:16）

### P0 修复：明明在学习页、明明在往前翻，却被判「无法识别」→ 回课程页 → 整门课放弃

用户质问：**「为什么要回课程页，就是就是在学习页面，但是它无法继续学习了，
即使无法识别也应该下一节才对啊」** —— 这句话是对的，旧实现有三个错：

#### 1. 纯文本章节根本没被认出来（每个白花 5~6 秒，还累加成"连续无法识别"）

从用户 11-22 导出的真实 DOM 快照
`record/DOM/20261122/001812_未识别页面_1` 解出来的事实：

```html
<div class="prev_title" title="第二节 华夏初立">第二节 华夏初立</div>
<ul class="prev_ul clearfix">
  <li class="active" cardid="1209675773" id="dct1">…第二节 华…</li>   <!-- 只有 1 个卡片 -->
</ul>
<iframe id="iframe" src="/mooc-ans/knowledge/cards?...&knowledgeid=1211178756&num=0">
<div id="prevNextFocusNext" class="… prev_next next fr …"
     onclick="PCount.next('1','1211178756','265852000','155480978','',true)">下一节</div>
```

正文由 `uParse(".ans-cc")` 渲染，**页面上没有任何 `ans-attach-online`**，
所以 12 个选择器一个都匹配不上 → 判「无法识别」。

日志证据（每一页 chapterId 都在变，说明一直在正常翻页）：

```
00:47:50 该页面无法识别（第 1 次）   chapterId=1211178773
00:48:14 该页面无法识别（第 3 次）   chapterId=1211178886
00:49:22 该页面无法识别（第 9 次）   chapterId=1211178892
00:49:45 连续 10 页都无法识别，结束本课程
```

修法：新增 `_QUICK_TEXT_JS` + `_is_text_chapter_fast()`，**一次 JS（实测 0.004~0.016 秒）**
判定「单卡片纯文本章节」，`page_message()` 直接返回 `{'文本': [True]}`（已知页面，正常翻页、
不累计未知次数）。

判据刻意保守，四项全满足才算：
1. 有章节标题栏 `.prev_title`；
2. **没有** `[class*="ans-attach-online"]`（有任务点就绝不吞）；
3. 卡片只有 1 个（`dct1`）—— 截图里那种 `1 正文 / 2 视频 / 3 ppt` 一律不算，走完整识别；
4. 卡片帧里已经渲染出正文（≥30 字）且**没有** `video/audio/embed/object/insertdoc` 等媒体元素。

#### 2. 「点下一节」只会点击，而它是 `div + onclick`，点不到就彻底卡住

`#prevNextFocusNext` 是 `<div>`，不是链接，**没有 href 可直连**；一旦被水印/遮罩/
焦点问题挡住，点多少次都不生效。新增 `_force_next_chapter()`：直接执行它 `onclick` 里的
`PCount.next(...)`（`new Function(code)()`），不需要可见、不需要焦点、不过命中测试。

`click_next_page()` 在点击路径全部失败时**先走这条兜底**，成功就清零计数继续，
不再把「点了没反应」直接升级成「找不到按钮 → 回课程页」。

真机冒烟验证（真实 Edge + 复刻真实 DOM）：`PCount.next` 被真的调用，参数
`['1','1211178756','265852000','155480978','',true]` 与 onclick 完全一致。

#### 3. 在学习页上，永远不许回课程页

新增 `_is_study_page()`；`main()` 的 `lost` 分支改为：

- 还在学习页（`studentstudy?chapterId=`）→ **不回课程页**，直接 `_force_next_chapter()`
  推进后继续 `run()`（最多 3 次）；
- 只有学习页上连续 3 次都推进不了，才回课程页重新定位；
- `run()` 里「同一页连续认不出」的上限，也是**先 force 推进**，force 不动才算真卡住。

#### 4. 顺手：卡片刚切换、播放器还没插进 DOM 时不要急着跳过

章节内是卡片标签（`dct1` 正文 / `dct2` 视频 / `dct3` ppt），「下一节」实际就是切到下一个卡片。
切换后播放器要过一会儿才插进 DOM，这段时间页面「看起来什么都没有」——旧代码立刻判
「无法识别」并点下一节，等于把刚切出来的视频/ppt 整页跳过去（用户这门课 51 个任务点
只完成 11 个）。

新增 `_page_rendered()`：卡片帧里既没正文也没媒体/任务点元素 → `page_message()` 立刻返回空
（50ms，不再白扫 2 秒），交给 `wait_page_message()` 重试（间隔 1.0 → 1.5 秒，多给渲染时间）。

#### 验证

- 新增 `tests/smoke_text_chapter_live.py`（**真实 Edge** + 本地 HTTP，页面结构照抄真实快照）：
  14 条断言全 PASS —— 文本页 0.006s 认出、`PCount.next` 真的被调用、
  多卡片/带任务点/未渲染三种情况都**不**判文本、超长正文 0.016s、无按钮不崩。
- 新增 `tests/test_text_chapter_flow.py`：22 条静态守卫（快速路径必须在扫选择器之前、
  四项判据齐全、media 里不许含 iframe、force 优先于累加 error_num、学习页判断在回课程页之前）。
- 全量 **76 套件全绿**。
- 产物：`dist/start-26.11.22.1216.exe`、`课程学习助手_审查包_26.11.22.1216.zip`。

#### 仍未支持（下一步）

章节内多个卡片时，程序只会顺着「下一节」一张张走；如果某个卡片的播放器/文档
需要**点击标签本身**才加载，仍可能漏。抓一份多卡片章节（`dct2` 是视频）的 DOM 即可补上。

## 26.11.22.1148（2026-11-22 11:48）

### P0 修复：「学着学着不学了」——整门课被误判结束，且再也进不去

用户导出日志（00:47 ~ 01:00）＋11 张诊断截图，完整还原了现场。

#### 现场

```
00:49:35 该页面无法识别（第 10 次）
00:49:45 连续 10 页都无法识别，结束本课程（避免空转）
00:49:51 已进入「我学的课」列表            ← 其实还停在学习页，耗时 0.01s
00:50:07 没看到《中华民族共同体概论》，当前看到的课程：['返回课程']
00:53 ~ 01:00 三轮重试，每轮干等 180 秒
01:00:39 回不到课程页，结束本课程
```

诊断截图看得清清楚楚：这些"无法识别"的页面**就是纯文字章节**
（「第二节 形成统一经济体系」，页面只有「上一节 / 下一节」，没有任何任务点）。

#### 缺陷①（决定性）：学习页地址被当成"课程列表"

`_COURSE_LIST_URL_MARKS = ('/visit/courses', '/mycourse', '/course/list')`，
而学习页地址是 `/mycourse/studentstudy?chapterId=...` —— **含 `/mycourse`**。

于是恢复流程第一步 `_looks_like_course_list_url()` 就返回 True：
菜单不点、页面不导航（0.01 秒），直接在学习页上找课程卡片，
只找到一个「返回课程」按钮 → 三轮重试全部失败 → 整门课结束。

修法：`studentstudy` / `studentstudycourse` 明确排除。

#### 缺陷②：不同章节的纯文本页被累加成「连续无法识别」

`unknown_count` 只增不减地跨章节累计。这门课连着 11 个文本章节，
于是越过阈值被"避免空转"直接掐掉。

修法两层：
1. `page_message()` 兜底识别「纯文本章节」——没有任何已知模块，但
   有章节标题栏 / 章节导航，或地址仍是 `studentstudy?...chapterId=`，
   就返回 `{'文本': True}`（dispatch 会安全忽略），走正常翻页流程。
   反例保护：页面上若还有 `ans-attach-online` 附件元素却没认出来，
   **不**算纯文本，继续按未识别处理（要留 DOM、要计数，不能静默跳过）。
2. `unknown_count` 之外新增 `unknown_same`：只有**同一页**（chapterId 没变）
   连续认不出才算卡住，换页即清零。

#### 缺陷③：手动等待课程注定等满

旧逻辑等 180 秒 × 3 轮 = 9 分钟，判据只有「窗口句柄数量变了」——
用户在**同一个标签页**里点进课程是不会有新窗口的，所以它永远等满、永远失败。
改为 60 秒，并同时认「地址变成了学习页」。

### 验证

- 新增 `tests/test_course_reentry.py`：18 条断言（学习页不算列表、
  纯文本章节识别 5 个场景含反例保护、同页计数、60 秒等待与同标签页判定）
- 全量 **75 套件全绿**，exe `--selftest` PASS

### 尚未支持（下一个版本）

诊断截图 `003243` 显示，这门课用的是学习通**新版「章节详情」页**：
章节内部用标签页切换「1 第二节… / 2 视频 / 3 ppt」，视频和 ppt 是独立标签。
当前版本只识别旧版卡片式任务点，**这些标签里的视频/ppt 会被跳过**。
本次已让这些页面按「文本」正常翻页并自动落 DOM 快照
（`record/DOM/<日期>/<时间>_文本/`），拿到那份 DOM 就能补上标签页支持——
在没有真机结构的情况下硬写选择器只会再犯"照猜写代码"的错。

## 26.11.22.0006（2026-11-22 00:06）

### UI 重排：设置页大片空白、窗口拉不动、按钮之间大缝

用户反馈「整体逻辑混乱、UI 大面积留白、无法调整大小」。用脚本真实渲染截图比对后，
定位到 6 个独立问题（都不是审美问题，是布局代码写错了）。

#### 1. 设置页卡片内的大片空白 —— 行权重加错了行

```python
ui.rowconfigure(3, weight=1)          # 第 3 行 = 「窗口置顶」
self.parent.rowconfigure(3, weight=1) # 第 3 行 = 「保存设置」
```

给这两行加权重，等于**让它们吃掉所有多余高度**：界面设置卡片被拉得老高，
「窗口置顶」开关停在半空，下面一大片空白；保存按钮被推到最底下，
离上面的卡片隔着一大片空白。两行权重全部删掉。

#### 2. 左列中间空一大块 —— `rowspan=2` 把「账号信息」挤下去了

「高级设置」原来 `grid(row=1, column=1, rowspan=2)`，跨了第 1、2 行。
grid 的行高取该行所有单元格的最大值，于是第 2 行被高级设置撑得很高，
同在第 2 行的「账号信息」（左列）就被推到很下面，左列中间自然空出来。

改法：左右两列各用一个容器 frame 独立堆叠卡片（`self._left` / `self._right`），
不再共用同一套行号，谁也不受谁的高度影响。

#### 3. 窗口拉窄后右列整个消失

设置页固定两列，窗口一窄右列直接被挤出可视区（用户截图里只剩左半边）。
现在按**逻辑像素**判断宽度（150% 缩放下 Tk 报的是物理像素，820 逻辑 = 1230 物理，
不折算阈值永远够大、单列永远不触发）：

- 宽度 < 900 → 左右两列上下叠成单列
- 宽度 > 940 才切回双列（40px 回差，防止在阈值附近来回抖）
- 各输入框/下拉框改成 `sticky="ew"`，跟着卡片拉宽，不再固定 140 像素

#### 4. 「保存设置」看不见

原来在滚动区域内最底部，内容一长就必须滚到底才找得到。
现在移到滚动区**外面的固定底栏**（`start.py` 建 `settings_footer`，
`SettingsPanel(footer=...)`），永远贴在窗口底部。

#### 5. 主界面按钮之间的大缝

按钮列号写死在创建时（0~4）。运行中隐藏「开始学习/开始考试」后，
右侧空出一整列，剩下的按钮还挤在原来那几格里。
新增 `_sync_toolbar()`：按**当前可见的按钮**重新均分整行，并把日志区的
`columnspan` 跟着调整；所有按钮 `sticky="ew"`。运行/空闲切换处都调用它。

#### 6. 各页面文本框不跟着窗口长

- 成绩页把权重加在第 0 行（下拉框那行），文本框反而纹丝不动 → 改到第 1 行
- 学习记录 / 题库 / 帮助 / 报错日志页都没给文本框所在行加权重，
  窗口拉大只有中间一条窄框、两边全空 → 统一补上
- 空日志框原来是一行红字挂在顶上，下面是巨大白框 → 改为居中灰色空状态，
  且只在「确实还没有日志」时显示（旧 `check_update` 会把它重新贴到日志上）

#### 7. 窗口尺寸

- `minsize` 写死 860×560，在 125%/150% 缩放的笔记本上已接近整屏宽，
  用户会觉得「拉不动」。改为跟屏幕走：宽 `min(820, 屏幕 50%)`、高 `min(600, 屏幕 50%)`；
  下限必须明显小于 900 的双列阈值，否则永远进不了单列
- 初始尺寸从「控件最小需求」改为「屏幕的 74%×80%」，并且永不超过屏幕
- 记住用户拉出来的大小：关闭时写 `ui/window.json`，下次启动还原

### 验证

- 新增 `tests/capture_ui.py`：真实创建窗口，抓主页/设置页(宽)/设置页(窄)/帮助页/学习记录页

- 全量 **74 套件全绿**，源码 `--selftest` PASS，exe `--selftest` PASS

- 只在 1920×1200、150% 缩放这一种环境下渲染验证过；100% / 125% 缩放下的

## 26.11.21.2350（2026-11-21 23:50）

### P0 修复：「文本很多、下一页在最下方」时卡 56 秒且找不到按钮

用户现场：某一章节页面正文极长，翻页按钮在最底部，程序卡在那里不动。
较老的那份导出日志（`课程学习助手_完整日志_20261120_225214.zip`）给出铁证：

```
21:34:22 跳转下一页
21:35:18 暂时没找到「下一页」按钮，等一会儿再点     ← 56 秒
21:35:27 跳转下一页
21:36:22 暂时没找到「下一页」按钮                  ← 55 秒
22:09:49 跳转下一页
22:10:45 暂时没找到「下一页」按钮                  ← 56 秒
```

#### 1. 56 秒是算出来的，不是网络慢

工程全局 `implicitly_wait(2)`，`_find_next_button` 有 **6 条 XPath**，
调用方扫 **1 个顶层 + 4 个 iframe** = 5 个上下文：

`6 × 5 × 2 秒 = 60 秒` —— 与实测 55~56 秒完全吻合。

`_find_next_button` 是典型的「探测型查找」，却**没有**包在
`core.navigation.probe_mode()` 里（同一天早些时候修课程列表卡顿时立过这条规矩，
这次漏了）。现在兜底路径已包进 `probe_mode`，改为 0 等待。

#### 2. 长文本页上永远找不到按钮

旧 XPath `//*[contains(normalize-space(.), "下一页")]` 在超长正文页上：

- 会先命中一串**祖先 div**（整块正文里都含「下一页」三个字）；
- 而且对每个元素都求整棵子树文本，复杂度是 O(n²)；
- 旧代码只看 `nodes[:4]`，真正的 `<a>` 排在第 5 个以后 → 永远找不到；
- 而且只下钻一层 iframe，学习通「外层壳 → cards → 模块」的按钮根本扫不到。

#### 改法：一次 JS 扫完整棵帧树再点

新增 `_NEXT_SEARCH_JS` / `_click_next_by_js()`：

- 同一个脚本里递归 `contentDocument`（同源帧，最多 4 层），**不切 frame**
  —— 顺带避免把播放器弄失焦（8 月那次的教训）；
- 只扫交互元素 `a/button/input/[onclick]/[class*=next]/[id*=next]`，
  并且跳过子节点 > 3 的元素，不再对祖先大 div 求文本；
- 打分选择：`#prevNextFocusNext`（学习通正版章节导航）= 5，
  精确文字「下一页/下一节/下一章」= 3，class/id 含 next = 1；
  同分优先外层帧，其次取**页面最下方**那个（用户反馈按钮就在最底部）；
- `scrollIntoView` 再 `click()`，失败退化为 `initMouseEvent` 派发；
- 候选上限 3000，避免超长页退化成 O(n²)。

`click_next_page()` 现在是「先 JS，失败再 Selenium 兜底」。
兜底路径同时修了 `nodes[:4] → nodes[:40]`。

#### 3. 顺手清理死代码

`_try_click()` 自 2026-11-19 的 P0-5 修复后只会返回 `clicked/none`，
永远不会返回 `finished`，所以 `if result == 'finished': 打印🎉撒花` 是**不可达分支**。
而 `test_stuck_recovery.py` 里还有一条断言专门检查这行字符串存在 ——
等于在给死代码背书。已删分支，并把断言改为检查真正生效的完结判据
（`本页任务点已全部完成，且没有下一页`）。

#### 4. 诊断信息补全

找不到按钮时现在会打印耗时与扫描面：

```
暂时没找到「下一页」按钮（耗时 0.3s，未找到候选（扫描 3 文档/2 帧，跨域跳过 0）），等一会儿再点
```

正常路径如果超过 2 秒，会单独警告 `[耗时] 找「下一页」x.xs（来源）`，
一眼能看出是不是又退回了慢路径。

### 新功能：提交后按平台判定回填缓存（只存答对的）

需求来源：部分测验提交后，结果页会在每题后标出对/错。用户希望**答对的直接固化进
缓存，答错的不写** —— 这样下次遇到同题能直接命中，而错误答案不会被永久钉死。

实现（`Answer._harvest_correct_answers()`，在 `save_score()` 之后执行）：

1. 采集结果页题块（`.questionLi` / `.TiMu` / `.mark_item` 等，宽收集），记录每个
   题块的 class 与文本；
2. **只认明确的「答对」标记**：class 含 `dui`、或文本含「回答正确 / 答案正确」；
   class 含 `cuo`、或文本含「回答错误 / 答案错误」→ 一律不写；
3. 用本题**实际提交过**的答案（`num_answer_dit`）回填，不从页面反推、不猜；
4. 写完打印「答对 N 道已写入缓存，答错/未判定 M 道不写缓存」。

**三道安全约束（宁可少缓存，不可缓存错）**：

| 约束 | 原因 |
|---|---|
| 题块数量必须等于本次题目数，否则**整体放弃** | 数量错位会把 A 题的答案记到 B 题头上，缓存写错是长期污染 |
| 只认明确「答对」标记，认不出就当没有 | 把答错当答对会给缓存投毒 |
| 没有记录到我们提交的答案时跳过 | 避免缓存空答案 |

识别不到题块时会打印「结果页没有识别到题块（可能是没有对错标记的页面）」；
数量不符时会额外抓一份 DOM 到 `record/DOM/`，方便按真实结构校准选择器。

**测试**：新增 `tests/test_quiz_harvest_cache.py`（9 项），覆盖「一题对一题错只写对的」
「数量不符整体放弃」「无题块静默」「无答案不缓存空值」「submit 调用顺序」。

## 26.11.19.1527（2026-11-19 15:27）

### 修复：启动与保存设置闪一堆黑窗口、更慢

用户反馈：一启动就闪一大堆黑窗口，点「保存设置」又闪一大堆，而且比之前更慢。

**根因（已实测复核）**：程序用 `--noconsole` 打包，GUI 进程**没有控制台**。
此时只要调用任何控制台程序（`icacls` / `taskkill` / `msedgedriver --version`），
Windows 就会为它**新建一个控制台窗口** → 用户看到黑窗闪一下。

放大链：

| 环节 | 旧行为 | 次数 |
|---|---|---|
| `save_secret()` 写一个凭据 | 对 tmp 做一次 `icacls`，replace 后再对目标做一次 | **2 次/字段** |
| `_serialize_for_disk()` 一次保存 | 重新加密 4 个敏感字段（API / MeoW / 密码 / 手机号） | **8 次 icacls** |
| GUI 启动时 `ConfigManager.__init__` | `_migrate_secrets` 即使「无需迁移」也 `ok=True`，于是无条件重写 JSON → 又加密 4 个字段 | **又 8 次** |
| 每个 `icacls` | 进程创建 + 等待（本机实测 30~60ms） | **≈0.3~0.5 秒纯等待** |

所以「一启动闪一大堆 + 保存设置再闪一大堆 + 更慢」是同一个原因。

**修复**：

1. **新增 `core/subproc.py`**：`run_hidden()` / `popen_hidden()`，Windows 下同时带
   `CREATE_NO_WINDOW` 与 `STARTF_USESHOWWINDOW` + `SW_HIDE`（有些程序只认后者）。
   全工程 5 处外部命令调用全部改走它：`credential_store`（icacls）、`driver`（两处
   `--version`）、`runner`（taskkill、子进程 Popen）。
2. **凭据值未变化时直接返回**（`save_secret`）：不重新 DPAPI 加密、不重写文件、
   不碰权限。这是消除「保存设置闪一堆」的关键——没改的字段一个进程都不起。
3. **启动时不再做无意义的重新加密**：`_migrate_secrets` 改为返回
   `(ok, changed, note)`，只有 `changed=True`（真的把明文迁进了凭据库）才备份 +
   重写 JSON。以前每次启动都白跑一轮。
4. **`_restrict_permissions` 加进程内路径缓存**：同一路径只收紧一次。
5. **修掉一个一直存在但被静默吞掉的 bug**：旧代码把 `'%USERNAME%:F'` 直接传给
   `icacls`，而 `subprocess` 不经 shell **不会展开** `%USERNAME%`，icacls 收到字面量
   后必然失败（错误被 `capture_output` 吞掉）——**文件权限其实从未真正收紧过**。
   现在改用真实用户名，实测 `returncode=0`，权限真的生效了。
6. `icacls` 不再用 `text=True`：它的输出是系统 ANSI 编码（中文 Windows 为 GBK），
   文本模式会在读取线程里抛 `UnicodeDecodeError`。只需要 `returncode`，用 bytes。

**效果（可复核）**：

| 场景 | 修复前 | 修复后 |
|---|---|---|

| 保存设置（未改动敏感字段） | 8 次 | **0 次** |
| 保存设置（改了 1 个敏感字段） | 8 次 | **1 次（且不闪窗）** |
| 启动额外等待 | ≈0.3~0.5 秒 | **≈0** |

### 问题 1：单选题被点多个字母（P0）

`AnswerResolver.resolve()` 没有按题型限制答案数量。题库返回的字母串
（如 `A,B`，来自 `ai_wen_da` 的 `selected_options` / 脏数据）被原样全点；
单选页后点的字母覆盖前面的，最终写入错误答案。
实测复现：`resolve(单选题, ['A,B']) -> ['A','B']`。

- 修复：按 `question.type_name` 区分 —— **单选题/判断题只取 1 个字母**，
  多选题才允许多个；返回前再做一次兜底裁剪。
- 兼容：纯桩测试里的简化 `Q` 没有 `type_name`，用 `getattr` + 选项数保守判断。
- 新增日志：「题库返回=… → 解析字母=…（题型=…）」，便于核对答案是否正确；
  脏数据被裁剪时明确打印原因。

### 问题 2：只答 2 题就结束（P0）

真机采集 `exam_probe/snap_0012/top.html` 确认翻页按钮是
`<div class="nextDiv"><a class="jb_btn ...">下一题</a></div>`，文本为「**下一题**」。
而原 `_go_next_by_text()` 只找「下一步」，在真实考试页**根本点不到按钮**，
翻页完全依赖上一版整合时加的 `.nextDiv` CSS 兜底（未经本校真机验证）。
再加上 `run()` 一遇到「题号重复」就 `break`，DOM 稍慢就会误判到最后一题。

- 修复 `_go_next_by_text()`：文本同时认「下一题」和「下一步」，返回是否点中。
- 修复 `_go_next()`：**优先按文本定位**；CSS 兜底只在文本找不到时使用，
  且必须校验元素文本含「下一」，避免误点标记/交卷按钮；
  等题号变化时改用 `_locate_question_box()`（与读题同一套定位），
  最多等 7 秒。
- 修复 `run()`：题号重复时先等待重试（最多 3 次 × 1.5 秒），
  连续重复才判最后一题，不再第 2 题就收尾。
