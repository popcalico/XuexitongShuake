一、浏览器选择相关

  1. 问：在设置页面中，浏览器如何选择？
     答：建议使用 Chrome；如果 Chrome 不可用，可以切换到 Edge。

  2. 问：浏览器驱动还需要手动下载吗？
     答：不需要。程序会先使用本机已有的驱动，其次读取程序目录或数据目录下的 drivers 文件夹，
     最后按本机浏览器版本自动下载匹配的驱动。只有自动获取失败时，才需要手动处理。

  3. 问：如何查看 Chrome / Edge 的版本号？
     答：在浏览器地址栏输入 chrome://version 或 edge://version，页面第一行就是完整版本号。

  4. 问：Chrome 驱动在哪里下载？
     答：https://googlechromelabs.github.io/chrome-for-testing/
     请下载与本机 Chrome 版本一致的 chromedriver。

  5. 问：Edge 驱动在哪里下载？
     答：https://developer.microsoft.com/microsoft-edge/tools/webdriver/
     请下载与本机 Edge 版本一致的 msedgedriver。

二、驱动地址相关

  1. 问：驱动地址是什么？
     答：它是浏览器驱动的可执行文件路径，不是浏览器本身的路径。

  2. 问：版本一致时驱动地址如何配置？
     答：在设置页面点击“选择文件”，选中 chromedriver 或 msedgedriver 可执行文件即可。

  3. 问：自动下载失败、版本又不一致怎么办？
     答：先把对应版本的驱动解压出来，放进程序同级的 drivers 文件夹（可以带子目录），
     或者在设置页面把“驱动地址”指向解压出来的驱动文件，然后重新启动程序。

三、其他设置相关

  1. 问：字体和信息设置有什么要求？
     答：字体按自己的习惯选择即可，建议开启窗口置顶。信息按实际情况填写；
     课程名称要和平台里显示的名称完全一致，建议直接复制粘贴。

  2. 问：答题如何设置？
     答：在“章节测验”里选择 DeepSeek AI（支持常见题型）。设置完务必点击保存并确认，
     再回到主页启动程序。

  3. 问：倍速应当如何设置？
     答：建议 2 倍速。倍速过高可能导致已完成的任务点被重置；运行中想改倍速需要重启程序。

  4. 问：AI 接口 / API Key 怎么配置？
     答：设置页最下方「AI 接口（任意 OpenAI 兼容服务）」里填三项：
     API 地址（服务商的基地址，如 https://api.deepseek.com、
     https://api.openai.com/v1、http://localhost:11434/v1）、
     模型名称（如 deepseek-chat、qwen-plus、gpt-4o-mini）、
     API Key（设置页上方「API Key」一栏）。
     任何兼容 OpenAI chat/completions 格式的服务都能用，Key 不要求 sk- 开头。
     API Key 就在这组的第一行，与地址、模型放在一起；点右侧眼睛可显示明文。
     填好点「测试连接」验证，再点保存。

四、程序相关

  1. 问：点击启动后没有反应怎么办？
     答：先关闭程序，右键以管理员身份重新运行；仍然没有反应时，可以尝试直接运行主程序文件。

  2. 问：选择“不作答”时，启动后会发生什么？
     答：程序会自动打开浏览器并登录，进入课程后按设置处理视频、PPT、音频等内容，
     跳过章节测验。遇到问题可以到“报错日志”页面查看原因。

  3. 问：提示“无法加载扩展”怎么办？
     答：先确认浏览器与驱动版本一致；不一致时按上面的方法更换驱动。
     如果版本一致仍然报错，可以换另一个浏览器再试。

五、更新相关

  1. 问：如何检查更新？
     答：主页点击“检查更新”即可；也可以直接到项目发布页下载新版本。

七、消息推送（MeoW）

  1. 问：怎么开启手机通知？
     答：在“高级设置”最下方找到“MeoW 推送”，打开“启用通知”，填入自己的设备 URL，
     点“发送测试推送”确认能收到。手动结束、账号结束、课程结束、详细错误、签到、
     日志导出等事件会推送；「开始学习」不再推送，也不会发每日汇总或定时进度快照。

  2. 问：设备 URL 会泄露吗？
     答：它只保存在本机 accounts.json，不会写进仓库或日志包；导出日志时会自动打码。
     请不要把填好 URL 的 accounts.json 发给别人。

  3. 问：通知内容长什么样？
     答：只用纯文本（HTML 表格在系统通知栏会显示得很乱，已放弃）。第一行是一句
     摘要，通知栏直接可见；后面是明细行，点进 App 展开查看。消息按
     「学习进度 / 异常告警 / 签到 / 工具」分类，新版 App 可分类筛选。

  4. 问：为什么有时没收到通知？
     答：接口限制 3 秒 1 条、每分钟 15 条、每小时 60 条、每天 1000 条，程序会在本地挡住超额消息；
     另外超时或服务端 500 时送达结果不确定，程序不会自动重试，避免重复打扰。

八、答题与讨论策略

  1. 问：“无法处理的题”两个选项有什么区别？
     答：默认“AI 尽力完成”：填空题、简答题会读题干、调用你配置的 AI 模型作答并填进作答区，
     会消耗 API 额度；数不出空位、AI 没答出、写不进去时自动降级为截图跳过，不会卡住。
     “截图跳过”恢复旧行为，只留图不联网。计算题、连线题两种策略下都直接跳过。

  2. 问：讨论怎么设置？
     答：在“讨论”里选 DeepSeek AI 即启用（这个下拉名沿用旧叫法，实际调用你在
     「AI 接口」里配置的模型）；默认由 AI 直接生成 30~50 字的简短回复。
     “抄已有回复”默认关闭，打开后才会随机抄一条现成回复。
     “讨论范围”默认“任务点内全部讨论”；“全部讨论（需真机校准）”是预留开关，
     需要确认学校讨论区页面结构后才能完整遍历整门课程。

  3. 问：填空题填错了怎么办？
     答：答案只写入作答区，不会自动提交（提交策略仍由“答完题后”控制）。
     提交前可以在页面上自行核对修改；不确定的题可在 record/图片题/ 下找到留档截图。

九、课程考试

  1. 问：怎么使用“自动完成考试”？
     答：在功能设置里选“自动完成考试”并保存。程序会先尽力点开课程页的“考试”入口，
     但选哪一场考试、以及考试说明页的“进入考试”按钮都由你自己点——一旦进入，
     倒计时不会停止，离开或退出界面也不暂停，截止会自动提交。
     程序检测到答题页后自动逐题作答；答完默认停在页面上不交卷，请自行核对后手动交卷。

  2. 问：为什么默认不自动交卷？
     答：提交不可逆，且考试作答次数有限。确需自动交卷时，在设置页“课程考试”里打开
     “允许按阈值自动交卷”（打开时会有二次确认弹窗），并设置阈值、撤销秒数、
     剩余时间保护。程序只会在答题率达到阈值、剩余时间充足、监控字段全部关闭、
     撤销窗口走完、且页面上确实找到“交卷”按钮时才提交；提交失败绝不自动重试。
     阈值沿用“搜到/点到的题”比例，不是正确率。

  3. 问：选项顺序和题库答案对不上？
     答：考试页 randomOptions=true 会把选项打乱，页面上显示的 A/B/C/D 只是位置。
     程序按 span[data] 里的真实字母定位，题库返回选项文本时按文本反查，
     不会按显示位置点，也不会随机猜答案。

十、OpenAI 兼容 AI 接口

  1. 问：能接哪些服务？
     答：任何提供 OpenAI chat/completions 格式接口的服务：DeepSeek、OpenAI、
     通义千问 / 豆包 / 月之暗面等国内厂商的兼容端点、各类中转代理、
     以及本机 Ollama / vLLM 等。只要地址和模型名对得上即可。

  2. 问：四个输入框分别填什么？
     答：「API 地址」填服务商基地址（SDK 会自动拼 /chat/completions，
     例如 https://api.openai.com/v1；本地 Ollama 填 http://localhost:11434/v1）。
     「模型名称」填文本答题用的模型。
     「视觉模型」选填，用于图片题；留空则复用文本模型（文本模型不支持
     图片时，在这里单独填一个支持视觉的模型）。
     「超时」填单次请求秒数，0 表示沿用程序默认；网络慢或模型响应长可调大。
     API Key 就在本组第一行，任意格式都支持，不要求 sk- 开头。
     这组设置常驻显示，切换「章节/作业/考试」或选「随机答题」都不会隐藏。

  3. 问：怎么确认配置生效？
     答：点「测试连接」，程序会发一次极小的请求并把地址、模型、返回结果列出来。
     运行中每次 AI 请求也会在日志里打一行「AI 接口: ... | 模型: ...」，
     但不会打印 Key。测试按钮只在主动点击时才联网，不会自动重试。

  4. 问：不填这些新框会怎样？
     答：默认仍是 https://api.deepseek.com + deepseek-v4-flash，与旧版本行为一致，
     老配置可以直接沿用。填了就必须保证地址与模型名匹配，否则请求会失败；
     失败时程序只记日志并降级跳过该题，不会中断刷课。

  5. 问：哪些功能会用这个配置？
     答：章节测验 / 作业 / 题库 AI 兜底、图片题（视觉模型）、讨论自动回复、
     课程考试 AI 兜底。免费题库不受影响。

  6. 问：API Key 会泄露吗？
     答：配置只存本机 accounts.json；导出日志时配置字段和正文里出现的 Key
     都会自动打码（不再只识别 sk- 前缀）。请不要把 accounts.json 发给别人。

  4. 问：遇到人脸识别 / 抓拍 / 切屏监控怎么办？
     答：程序每次操作前都读页面上的监控字段，任一开启就立即停止，不尝试绕过。
     请不要用本程序规避学校的考试监管；平台风控与账号风险由使用者自行承担。

十一、独立「开始考试」（推荐）

  第九章的「自动完成考试」是设置页里的旧模式（按课程循环跑）。
  主页上另有一个独立的「▶ 开始考试」按钮，行为完全不同，推荐用这个：

  1. 问：点「开始考试」后程序会做什么？
     答：只启动浏览器并自动登录，然后**什么都不点**，等你自己在浏览器里
     选课程、选考试。程序在后台只读扫描所有标签页，识别考试页面链。

  2. 问：能识别哪些页面？确认开始考试页算吗？
     答：算，而且这是重点。程序识别整条页面链：
     考试列表页 → 确认开始考试页（考试须知 / 我已阅读并同意）→ 答题页，
     另外还有整卷预览页和考试查看页。识别到确认页会在日志里明确提示
     「识别到确认开始考试页」，不会静默跳过。考试列表嵌在 iframe 里也能识别。

  3. 问：「进入考试」按钮谁点？
     答：**必须你自己点**。那一步会启动倒计时，而倒计时一旦开始，离开界面
     也不暂停、截止会自动提交。程序绝不代点，也不勾选「我已阅读并同意」。

  4. 问：什么时候开始答题？答完会交卷吗？
     答：识别到答题页就自动逐题作答（题库优先 + AI 兜底）。答完**停在页面上
     不交卷**，日志会提示「请自行核对后手动提交」。程序绝不点交卷、绝不点
     确认弹窗、绝不刷新页面，之后继续监听；若你再进入另一场考试会继续作答。

  5. 问：需要设置什么？
     答：只要账号（手机号/密码）和浏览器配置正确即可；AI 接口那组按第十章填
     （答题方式用到 AI 兜底时）。不需要填课程名称，也不用选「自动完成考试」。
     只启动当前一个账号，不会开多个浏览器窗口。

  6. 问：怎么结束？
     答：提交完成后点主页「结束学习」即可。运行中随时可点它中止。

  7. 问：和旧模式冲突吗？
     答：不冲突。旧模式（设置页 radio=「自动完成考试」）保留兼容，
     但它是按课程循环跑的；新按钮是独立入口，两者互斥使用同一套日志与停止逻辑。

  8. 问：进答题页后程序立刻说「答题完成」，一题都没答？
     答：这是 26.11.11.1747 版的已知 bug，已在 26.11.12.1303 修复 ——
     当时识别到答题页却没把浏览器焦点切到那个窗口，于是在首页上找不到题，
     2 秒就误判完成。请务必用新版 exe。若仍出现，日志会打印
     「诊断：未读到题目 | window=... | title=...」和各类题目容器数量，
     把这段发回即可定位是窗口、页面加载还是平台改版。
     程序现在遇到 0 题会明确提示「不判定为完成」并继续监听重试，不会假报完成。

十二、直播讲座（26.11.12.1740 修复）

  1. 问：为什么直播讲座只放 20~30 分钟就被标记完成？
     答：旧版把时长 `1:27:10` 错算成「秒×60＋小时」= 601 秒（10 分钟），
     中间那段分钟被丢掉，睡够就无条件写「已完成」，平台任务点其实没打勾。
     新版改成正确解析 `H:MM:SS` / `MM:SS`，并且不再用「睡多久」判定完成。

  2. 问：现在怎么算完成？
     答：每 30 秒轮询一次，检查平台任务点是否出现 `ans-job-finished` 打勾，
     同时看播放器有没有暂停、剩余时间有没有在递减（暂停会尝试重新点播放）。
     只有平台打勾才写学习记录；到超时上限还没打勾就记失败、留诊断截图，
     日志明确打印「平台未确认完成，不写学习记录」，不会再出现假完成。
     超时上限 = 总时长×1.2 + 5 分钟（最多 3 小时），时长只用来算这个上限。

     3. 问：直播页空白 / 时长读不到会怎样？
        答：最多等 30 秒等播放器渲染；占位值（-0:00 / 空串）不会再挡住有效的
        「剩余时间」选择器。若最终仍读不到时长，**不会放弃这场直播**——
        因为完成判据是平台打勾，程序改用 3 小时绝对上限继续轮询，
        同时留一张诊断截图，日志会打印「改用绝对上限继续等待平台打勾」。
        结束只关确实新开的直播标签，绝不关掉最后一个浏览器窗口，
        并切回章节页，避免接着触发「课程被结束」。

     4. 问：修完还要注意什么？
        答：请在一门含直播讲座的课里跑一次，确认「直播时长」与实际总时长一致、
        出现「直播任务点已打勾」时平台确实打勾、不再有空时长报错。
        课程被异常结束的旧 P0/P1（error_num 全局、未识别页死磕）本轮未动。

十三、撤销新工作台、卡顿与主观题提交防护（26.11.12.2132）

     1. 问：新版 Qt Quick 工作台呢？
        答：试用反馈效果太差，已完整撤销并备份到 `_撤销备份_20261112_2041/`。
        当前版本只有经典界面；`dist/` 里两个 119MB 的旧工作台 exe 已移出，
        别误启动。运行中的旧程序不会热更新，请先「■ 结束学习」再换新 exe。

     2. 问：程序跑久了越来越卡，修了什么？
        答：主因是界面日志框无限追加（行数越多，插入和重排越慢）。现在每个
        账号的日志框最多保留 2000 行，超出时一次删掉 400 行旧日志；并且只在
        你本来就贴着底部时才自动滚到底，回看历史不会被打断。主日志和单账号
        明细仍完整落盘，界面裁剪不影响排查。另外把每行日志固定的两次
        建目录 / 查大小降成一次，长时间运行更轻。日志内容、格式、轮转规则
        一点没变。

     3. 问：简答题 / 填空题没答上，程序还会提交吗？
        答：不会了。以前「答题率」只看搜到、点到的题，10 题里空 1 道也有
        90%，照样点提交，空答案交上去就改不了。现在只要还有简答 / 论述 /
        填空 / 名词解释没答成（含 AI 没答出、作答区写入失败、答题报错、
        整题跳过），一律改为「仅自动保存」，并在日志里列出没答的题号，
        请你手动补答后再提交。计算题、连线题这类程序本来就答不了的题
        不算，不会耽误正常提交。

     4. 问：那我怎么知道该补哪几题？
        答：日志会打印「还有 N 道主观题未作答或未能确认答案已写入（第 X 题）」，
        对应题目的截图仍在 `record/图片题/`。提交按钮一个都不会点，放心核对。

     5. 问：听说有一场 7 道全是简答题，程序算出 100% 却交了白卷？
        答：确有其事，是另一台电脑上的旧版本（26.11.12.1322）跑出来的日志：
        旧版写完答案不回读，页面一个字没填进去也当成答了，7/7=100% 就
        自动交卷，而提交不可逆。现在有两道硬闸：写完必须回读到答案文本、
        并触发富文本编辑器同步；提交前还要求每道主观题都拿到「确认写入」
        凭据。任何一道没确认，一律只保存、不提交。纯客观题测验照旧。


十四、卡在某章节 / 自动退出（26.11.14.2305 修复）

     1. 问：为什么一直停在同一个章节，等半天也不往前走？
        答：以前「跳转下一页」点了就算成功，不验证章节真的换了；刷新时
        iframe 还没加载完，程序又把加载抖动误当成「换页了」，于是在同一节
        反复空转（真机日志里空转了 40 分钟）。现在只认 chapterId 这类稳定
        身份真的变化，真没前进就回课程页重新定位任务点。

     2. 问：附件下载页 / 空白节为什么会「无法识别」然后自动退出？
        答：这些节本身没有任务点，但旧版不认识它们，连续 10 次判为异常页
        就结束整门课。现在附件页和空白节会被识别成「无任务点」直接翻页；
        即使真卡住，也先刷新重试 3 次再放弃，不会第一次失败就退出。

     3. 问：手动跳过后程序自己退出了？
        答：全局的「找不到下一页按钮」计数会跨课程累积，累计 8 次就把课程
        判成「已完结」。现在每轮都清零，而且找不到按钮不再等于课程完结，
        改为回课程页重新定位。

     4. 问：日志刷得太多、越用越慢？
        答：字体解密和 AI 请求原本每行都往日志里写 INFO（一次解密十几行
        `Dumping ... table`），已压到 WARNING；连续无法识别时诊断截图也改成
        每 3 次存一张，减少大图写盘。
